# Руководство по Lua 5.4 в PerfUI (модуль PerfUI_Lua)

## 1. Введение и назначение

Модуль **PerfUI_Lua** предоставляет моддерам возможность писать **логику пользовательского интерфейса** на языке Lua 5.4:
- Обработчики нажатий кнопок, переключателей, ползунков, выпадающих списков.
- Интерактивные вычисления и форматирование данных.
- Одноразовые (`ui.timer`) и периодические (`ui.interval`) таймеры.
- Всплывающие уведомления (`ui.toast`).
- Получение токенов оформления (`ui.theme.color`).

> [!IMPORTANT]
> **Разделение ответственности:**
> Внешний вид интерфейса по-прежнему описывается декларативной XML-разметкой (`PerfUI_Markup`).
> Скрипты Lua предназначены для легковесной UI-логики.
> Тяжёлая логика (отрисовка 3D-компонентов, расчеты геометрии, обход сотен актеров) остаётся в C++.

> [!WARNING]
> **Безопасность скриптов:**
> Скрипты — это исполняемый код. Запускайте скрипты только из доверенных модов.
> Модуль изолирует скрипты в песочнице (запрещены `io`, `os`, `debug`, raw memory access, сеть и произвольный доступ к файловой системе), однако злонамеренный скрипт может попытаться исчерпать выделенные лимиты времени или памяти.

---

## 2. Архитектура и изоляция

- **Каждый мод получает свой собственный `ScriptHost`** с изолированным `lua_State`. Глобальные переменные одного мода никогда не видны другому моду.
- **Чистый C API без утечки заголовков:** Типы Lua (`lua_State*`, `lua.h`) не попадают ни в SDK (`PerfUIApi.h`), ни в публичные заголовки ядра `PerfUI_Core` или `PerfUI_Markup`.
- **Потокобезопасность:** Скрипты выполняются **только в UI-потоке**. Вызовы из фоновых игровых потоков должны маршрутизироваться через `PerfUI::Client::RunOnUIThread`. В Debug-сборке установлены assertions на проверку потока владельца.

## 3. Песочница и лимиты

### 3.1 Разрешенные и запрещенные библиотеки

| Статус | Библиотеки и функции |
| :--- | :--- |
| **Разрешено** | `base` (`print`, `assert`, `pcall`, `type`, `tostring`, `tonumber`, `select`, `ipairs`, `pairs`, `next`, `error`), `table`, `string`, `math`, `utf8`, `coroutine`, `collectgarbage("count")` |
| **Запрещено** | `io` (все функции ввода-вывода), `os` (доступ к системе и процессам), `package` (стандартный загрузчик), `debug` (интроспекция стека), `dofile`, `loadfile`, `load` с произвольным кодом, `collectgarbage("collect")` |
| **Безопасный require** | Собственный `require(name)`: разрешает загрузку модулей `.lua` только внутри папки скрипта мода; пути вида `..`, абсолютные диски (`C:/`, `/etc`) отвергаются с ошибкой. |

### 3.2 Лимиты выполнения (`ScriptLimits`)

Для защиты от зависаний игры и утечек памяти действуют строгие лимиты на каждый вызов скрипта:
- **Лимит инструкций:** по умолчанию 1 000 000 виртуальных инструкций на вызов. При превышении вызов прерывается ошибкой.
- **Лимит времени:** по умолчанию 50 мс на вызов (контролируется через `lua_sethook`).
- **Лимит памяти:** по умолчанию 16 МБ на экземпляр `ScriptHost` (собственный кастомный аллокатор `lua_Alloc`). При исчерпании скрипт завершается ошибкой OOM без аварийного падения игры.
- **Счётчик ошибок (Circuit Breaker):** после 5 подряд идущих ошибок хост переходит в состояние `disabled`, прекращает выполнение скрипта и оставляет интерфейс интерактивным.

## 4. Справочник API v1

### 4.1 Глобальная таблица `ui`

```lua
-- Поиск элемента по имени в текущем дереве интерфейса
local elem = ui.find("SaveButton") -- возвращает ручку UIElement или nil

-- Показ всплывающего уведомления (toast)
ui.toast("Операция выполнена успешно", "success") -- типы: "info", "success", "warning", "error"

-- Одноразовый таймер (задержка в секундах, колбэк)
local timerId = ui.timer(2.0, function()
    log.info("2 секунды прошло!")
end)

-- Периодический таймер (интервал в секундах, колбэк)
local intervalId = ui.interval(0.5, function()
    log.info("Тик каждые 500 мс")
end)

-- Отмена таймера или интервала по его ID
local cancelled = ui.cancel(timerId) -- true, если отменен

-- Чтение цвета темы оформления
local color = ui.theme.color("borderFocus")
-- Возвращает таблицу: { r = 212, g = 175, b = 55, a = 255, hex = "#D4AF37FF" }
```

### 4.2 Ручки элементов (`UIElement Handle`)

Ручки **не содержат сырых указателей**. Каждая ручка хранит `ElementId` и слабый наблюдатель `WeakElementRef`. Если элемент уничтожен (например, при хот-релоаде или перестройке дерева), вызов метода на ручке **не приводит к падению**: пишется предупреждение в лог, и метод безопасно возвращает `nil` или `false`.

#### Общие методы:
- `handle:id()` -> целое число ID элемента.
- `handle:name()` -> строковое имя элемента.
- `handle:isValid()` -> `true`, если C++ элемент ещё существует.
- `handle:isVisible()` -> `boolean` видимости.
- `handle:setVisible(bool)` -> установить видимость.
- `handle:isEnabled()` -> `boolean` доступности для взаимодействия.
- `handle:setEnabled(bool)` -> включить / выключить элемент.
- `handle:isFocused()` -> `true`, если элемент находится в фокусе ввода.
- `handle:opacity()` -> число `0.0 .. 1.0`.
- `handle:setOpacity(number)` -> установить прозрачность элемента.

#### Методы виджетов:
- `handle:text()` -> текущий текст (`Text`, `Button`, `TextInput`, `Checkbox`, `Slider`).
- `handle:setText(str)` -> установить текст.
- `handle:value()` -> текущее числовое значение (`Slider`, `ProgressBar`, `Checkbox`).
- `handle:setValue(num)` -> установить значение.
- `handle:isChecked()` -> `true`/`false` для `Checkbox`.
- `handle:setChecked(bool)` -> установить флаг `Checkbox`.
- `handle:selectedIndex()` -> индекс выбранного элемента (`ComboBox`, `TabBar`).
- `handle:selectIndex(index)` -> выбрать индекс.

### 4.3 Логирование `log`

Скрипт пишет в систему логирования PerfUI (в игре — в `SKSE.log` с префиксом `[Lua:<ModName>]` и указанием файла и строки):
```lua
log.info("Информационное сообщение")
log.warn("Предупреждение о некорректном состоянии")
log.error("Критическая ошибка логики")
```

## 5. Интеграция с разметкой (`PerfUI_Markup`)

В заголовке документа разметки указывается атрибут `script`:
```xml
<UI script="main.lua">
  <Panel name="Root" padding="16" gap="8">
    <Button name="BtnSave" text="Сохранить" onClick="onSaveClicked"/>
    <Checkbox name="SoundToggle" text="Звук" onToggle="onSoundToggled"/>
    <Slider name="VolSlider" min="0" max="100" value="50" onValueChanged="onVolumeChanged"/>
  </Panel>
</UI>
```

В файле `main.lua`:
```lua
function onSaveClicked()
    ui.toast("Настройки сохранены!", "success")
end

function onSoundToggled(enabled)
    log.info("Звук переключен: " .. tostring(enabled))
end

function onVolumeChanged(newVal)
    log.info("Новая громкость: " .. tostring(newVal))
end
```

### Приоритет колбэков
Если для одного имени (например, `onSaveClicked`) зарегистрирован и C++-колбэк через `loader.bindCallback(...)`, и Lua-функция в скрипте — **приоритет всегда отдаётся C++**. Lua-функция вызывается только тогда, когда C++ обработчик с таким именем не найден.

### Хот-релоад (Hot-Reload)
При изменении файла разметки или скрипта на диске:
1. Состояние скрипта сбрасывается (`host.reset()`).
2. Все старые таймеры и интервалы автоматически отменяются.
3. Старые ручки элементов становятся недействительными (`handle:isValid() == false`).
4. Загружается новый код скрипта и строится новое дерево элементов.

## 6. Расширение от C++ мода (`registerModule`)

Скрипт не имеет прямого доступа к памяти игры. Мод может безопасно экспортировать свои функции через кешированные значения:

```cpp
auto* host = PerfUI::Client::CreateScriptHost("MyMod");

host->registerModule("game", [](PerfUI::ModuleBuilder& m) {
    m.function("getPlayerHealth", []() -> double {
        return CachedPlayerHealth();
    });
    m.function("playSound", [](std::string soundId) {
        SKSE::log::info("Play sound: {}", soundId);
    });
});
```

В Lua:
```lua
local hp = game.getPlayerHealth()
if hp < 0.2 then
    game.playSound("UIHeartbeat")
end
```
Любые исключения C++, брошенные внутри функций модуля, перехватываются и преобразуются в стандартные Lua-ошибки без сбоя игры.

## 7. Типичные ошибки и их решение

1. **`attempt to use destroyed element 'MyButton' in method 'setText'`**
   - *Причина:* Дерево интерфейса было пересоздано (например, при перезагрузке разметки или очистке контейнера), а скрипт обращается к старой переменной.
   - *Решение:* Запросите элемент заново через `ui.find("MyButton")`.

2. **`instruction limit exceeded (max 1000000 per call)`**
   - *Причина:* Бесконечный цикл `while true do` или слишком тяжёлая рекурсивная обработка в скрипте.
   - *Решение:* Разбейте обработку на порции через `ui.interval` или перенесите тяжёлый цикл в C++.

3. **`time limit exceeded (max 50.0 ms per call)`**
   - *Причина:* Скрипт заблокировал UI-поток дольше положенного времени кадра.
   - *Решение:* Оптимизируйте вычисления, используйте C++ модули.

4. **`not enough memory`**
   - *Причина:* Скрипт выделил более 16 МБ памяти (например, конкатенация гигантских строк).
   - *Решение:* Не храните большие объемы бинарных или текстовых данных в Lua.
