# MapCanvas — виджет карты

`PerfUI::MapCanvas` (`include/PerfUI/MapCanvas.h`, `src/widgets/MapCanvas.cpp`) — карта: круглый
радар с игроком в центре (`MapMode::Radar`) или схема мира с камерой, зумом и панорамированием
(`MapMode::World`). Виджет не знает про Skyrim: всё, что он рисует, приходит через `IMapDataSource`.
Мод `QuestUI` наполняет этот источник из движка, `PerfUI` остаётся переносимым.

Живой пример с ходьбой по кругу — `examples/map_demo/` (в песочнице клавиша `F9`, переключение
режима — `M`).

---

## 1. Модель данных

```cpp
enum class MapMarkerKind { Quest, Location, Enemy, Custom };

struct MapMarker {
    std::uint64_t id{ 0 };                 // уникальный в пределах карты
    std::string   label;                   // подпись; пустая — рисуем только дистанцию
    MapMarkerKind kind{ MapMarkerKind::Custom };
    float x{ 0.0f };                       // метры, +X = восток
    float y{ 0.0f };                       // метры, +Y = север
    bool  active{ false };                 // текущая цель выбранного задания
    bool  discovered{ true };              // false: полупрозрачный маркер
    bool  sameSpace{ true };               // false: на карте не рисуется, только бейдж
    Color color{ Color::Transparent() };   // alpha == 0: цвет из темы по kind
};

struct MapPlayerState {
    float x{ 0.0f };
    float y{ 0.0f };
    float headingDeg{ 0.0f };              // 0 = север, растёт по часовой стрелке
};

class IMapDataSource {
public:
    virtual MapPlayerState player() const = 0;
    virtual std::span<const MapMarker> markers() const = 0;
    virtual std::uint64_t revision() const = 0;   // меняется при любом изменении данных
};
```

Цвета по `kind`, если цвет не задан явно: `Quest` — `theme.colors.textAccent`, `Location` —
голубой `{126,200,227}`, `Enemy` — красный `{214,86,78}`, `Custom` — `theme.colors.borderFocus`.

Формы: `Quest` — ромб, `Location` — круг, `Enemy` — треугольник, `Custom` — маленький круг.
Активная цель крупнее, плюс пунктирная линия от игрока и пульсирующее кольцо.

### Готовый источник

`VectorMapDataSource` — для тестов, примеров и одно-поточных сценариев:

```cpp
PerfUI::VectorMapDataSource src;
src.setPlayer(0.0f, 0.0f, 90.0f);          // x, y, курс в градусах
src.setMarkers({ markerA, markerB });      // revision++ сам
map.setDataSource(&src);                   // виджет источнику не владеет
```

### Своё приложение (мод)

Источник живёт в моде, виджет — в ядре. Правило: `markers()` обязан вернуть снимок, валидный
на всё время рендера кадра.

```cpp
class SkyrimMapDataSource final : public PerfUI::IMapDataSource {
public:
    PerfUI::MapPlayerState player() const override { return m_player; }
    std::span<const PerfUI::MapMarker> markers() const override { return m_markers; }
    std::uint64_t revision() const override { return m_revision; }

    // Вызывается с игрового потока, копирует собранные данные в UI-очередь.
    void pushFromGameThread(PerfUI::MapPlayerState p, std::vector<PerfUI::MapMarker> m) {
        PerfUI::Client::RunOnUIThread([this, p, m = std::move(m)]() mutable {
            m_player = p;
            m_markers = std::move(m);
            ++m_revision;
        });
    }

private:
    PerfUI::MapPlayerState m_player;
    std::vector<PerfUI::MapMarker> m_markers;      // только UI-поток трогает
    std::uint64_t m_revision{ 1 };
};
```

Данные собираются на игровом потока в снимок, в дерево UI попадаются только через
`Client::RunOnUIThread` — ядро не читает объекты игры из колбэка рендера.

## 2. Система координат и углов

Это единственное место, где легко ошибиться знаком, поэтому — явно.

- **Ось X растёт на восток, ось Y — на север** (не «вниз», как на экране).
- **Экранная Y растёт вниз.** Отсюда все «−» в формулах проекции.
- **`headingDeg`: 0 = север, растёт по часовой стрелке.** 90 = восток, 180 = юг, 270 = запад.
- **Азимут цели** тоже от севера по часовой: `atan2(dx, dy)`, а не привычный `atan2(dy, dx)`.

```
units → meters:  m = units * 0.01428                 (в Skyrim 1 м = 70 юнитов)
bearing(P) [deg] β = deg(atan2(P.x - p.x, P.y - p.y)) → нормализовать в [0, 360)
курс игрока:     h = headingDeg
относительный:   θ = β − h

radar, rotateWithPlayer = true:   screenX = cx + R · sin θ
                                  screenY = cy − R · cos θ
radar, rotateWithPlayer = false:  θ = β (север всегда вверх)
world (камера c, м/px = k):       screenX = cx + (P.x − c.x) / k
                                  screenY = cy − (P.y − c.y) / k
```

Смысл: при `rotateWithPlayer = true` курс игрока вычитается из азимута, поэтому «стрелка игрока»
всегда смотрит вверх экрана, а карта под ней крутится. При `false` угол не вычитается — север
сверху, маркеры стоят по абсолютным азимутам, игрок-треугольник рисуёт свой курс.

Проверено в тестах (`tests/MapCanvasTest.cpp`, группа 1): цель на севере при курсе 0 — над центром;
при курсе 90° — слева от центра; цель на востоке при курсе 90° — над центром.

## 3. Режимы

| Режим | Что это |
| --- | --- |
| `MapMode::Radar` | круглый диск: игрок в центре, масштаб — радиус радара |
| `MapMode::World` | карта мира: прямоугольное окно с камерой, зумом и панорамированием |

### Radar

Диск `min(width, height)/2 − 3` px, игрок в центре. `rotateWithPlayer` решает, вычитать ли курс
из азимута: `true` — стрелка игрока смотрит вверх, карта крутится; `false` — север всегда вверх.
Три кольца на 1/3, 2/3 и 3/3 радиуса с подписями в метрах. Цель дальше `radarRange` превращается
в стрелку на границе с реальной дистанцией.

### World

Прямоугольное окно внутри виджета (`viewRect`, отступ 2 px) с рамкой. Север всегда вверх —
курс игрока из азимутов не вычитается, стрелка игрока просто показывает его курс.

- **Камера** — центр в метрах (`cameraCenter`) и `metersPerPixel` (метров на пиксель, то есть
  «насколько крупно»). Границы масштаба задаёт `zoomLimits(min, max)`, по умолчанию 0.25…200.
  Провайдер мода может выставить их по размеру мира.
- **Следование за игроком** (`followPlayer`, по умолчанию включено): каждый кадр центр камеры —
  игрок. Любая явная навигация (`centerOn`, перетаскивание дальше порога в 6 px) следование
  выключает; кнопка «центрировать на игроке» (значок-мишень в правом верхнем углу окна, рисуется
  только когда следование выключено) возвращает и камеру, и следование. `centerOnPlayer()` —
  то же самое из кода хоста.
- **Отсечение**: метки вне окна не проектируются вообще. Активная цель — исключение: она
  остаётся в `m_projected` и рисуется стрелкой на той границе, через которую в окно входит.
- **Сетка** с адаптивным шагом: кандидаты из ряда 10, 20, 50, 100, 200, 500, 1000, 2000, 5000,
  10000 м и берётся первый, при котором между линиями выходит не меньше 64 px. Подписи шага —
  по осям: вдоль нижней границы X (восток, метры), вдоль левой Y (север, метры). Текущий шаг —
  `gridStepMeters()`, 0 если сетку не просили.
- **Кластеризация**: метки, чьи экранные позиции попадают в одну клетку размером
  `clusterPixelSize` (по умолчанию 26 px), рисуются одним значком с числом; подписи таких меток
  не выводятся. Активная цель не кластеризуется никогда. Тап по кластеру наводит на него камеру
  и приближает её (`zoomBy(0.5)`), иначе мелкие метки не разобрать. `clusterPixelSize(0)` —
  кластеризация выключена.
- **Линия «игрок → активная цель»** с подписью расстояния посередине (при `showDistances`).
  В радар-режиме ту же роль играет пунктир от центра.
- **Область**: `clampToBounds(minX, minY, maxX, maxY)` не выпускает камеру за край — половина
  окна всегда остаётся внутри. Если область меньше окна, камера держит её центр (иначе её
  прижимало бы к краю). `clearBounds()`/`hasBounds()`.

## 4. Настройки

| Метод | По умолчанию | Эффект |
| --- | --- | --- |
| `setDataSource(IMapDataSource*)` | `nullptr` | источник; `nullptr` безопасен — пустая карта |
| `mode(MapMode)` | `Radar` | режим |
| `radarRange(float meters)` | `300` | только `Radar`: метр → пиксель; `<= 0` отключает проекцию |
| `rotateWithPlayer(bool)` | `true` | только `Radar`: крутить карту под курсом или держать север вверх |
| `showGrid(bool)` | `false` | `Radar` — лучи сторон света, `World` — адаптивная сетка с осями |
| `showDistances(bool)` | `true` | подписи колец, «· 240 м» у маркеров, расстояние на линии к цели |
| `onMarkerClicked(cb)` | пусто | колбэк с копией маркера; `false` из `onPointerUp`, если мимо |
| `metersPerPixel(float)` | `2` | только `World`: масштаб камеры |
| `zoomLimits(min, max)` | `0.25 / 200` | только `World`: пределы `metersPerPixel` |
| `cameraCenter(Point meters)` | `(0,0)` | только `World`: центр камеры; выключает следование |
| `followPlayer(bool)` | `true` | только `World`: камера ездит за игроком |
| `clusterPixelSize(float px)` | `26` | только `World`: сторона клетки кластеризации, `0` — выкл |
| `clampToBounds(minX, minY, maxX, maxY)` | — | только `World`: область, за которую камеру не выпускаем |
| `clearBounds()` | — | снять область |
| `onBackground(cb)` | пусто | «назад» (`VK_BACK` 0x08, он же кнопка B/Back геймпада) в `World` |

Действия над камерой: `centerOnPlayer()`, `centerOn(meters)`, `zoomBy(factor, anchor)`
(`factor < 1` — приближаем; `anchor` — точка в пикселях вьюпорта, которая должна остаться на месте),
`panPixels(dPx)`, `panMeters(dMeters)`.

Размер: `measure()` даёт 160×160, если в `layout()` не заданы Fixed/Percent ширина и высота;
padding и min/max соблюдаются. Геометрия диска — `min(width, height)/2 − 3` px, всё остальное
(толщины, кегли, размеры маркеров) масштабируется коэффициентом `clamp(radius/80, 0.75, 1.75)`.

### Ввод

| Событие | `Radar` | `World` |
| --- | --- | --- |
| тап ЛКМ по маркеру / стрелке цели | колбэк `onMarkerClicked` | колбэк `onMarkerClicked` |
| тап ЛКМ по значку кластера | — | навести камеру и приблизить |
| тап ЛКМ по значку-мишени | — | центрировать на игроке, вернуть следование |
| перетаскивание ЛКМ | игнорируется | камера едет за курсором: вниз по экрану = на север |
| колесо мыши | игнорируется | зум вокруг курсора (`0.8` на себя, `1.25` от себя) |
| `onAction(NavDirection)` — правый стик, стрелки | игнорируется | камера: вверх = север, вправо = восток; шаг 48 px |
| `onKeyDown(0x08)` — «назад» | игнорируется | `onBackground`, виджет возвращает `true` |

Правило для стика: направление = **куда камера едет в мире**, а не куда смотрит игрок. Карта под
курсором при панораме движется вместе с курсором («бумагу тянем за собой»), поэтому `panPixels`
инвертирует Y.

`MapCanvas` — фокусируемый (`setFocusable(true)` в конструкторе) и участвует в графе фокуса как
**один** элемент: nav-события приходят ему в `onAction`, детей у него нет, выход — кнопка «назад».
Перетаскивание и колесо работают только когда виджет активен (`isVisible()`).

### Клик и различение тапа

`onPointerUp` ищет ближайшую метку в пределах `14 · scale` px (у дальней цели кликается стрелка
на границе, а не её реальное «несуществующее» место). Смещение курсора больше 6 px между press и
release считается перетаскиванием — клик не срабатывает. Промаха виджет не касается: `false`,
событие уходит дальше по дереву. Все точки событий пересчитываются из локальных вьюпорта в
координаты проекции (`localPoint + bounds().topLeft()`), иначе клик по смещённому виджету никогда
бы не попал.

### Цель вне текущего пространства

`sameSpace = false` на карте не рисуется. Если такая цель активна, внизу появляется строка
«&lt;имя&gt; — в другом месте» (или «Цель в другом месте» без имени).

## 5. Кэш и стоимость кадра

Проекция пересчитывается только когда изменён ключ:

```cpp
struct CacheKey { source ptr, revision, width, height, mode, radarRange,
                  rotateWithPlayer, showGrid, camera, metersPerPixel, clusterPx,
                  boundsMeters };
```

Совпал ключ — переиспользуются `m_projected` и `m_clusters`, `recompute()` не вызывается. Счётчик
`recomputeCount()` это наглядно показывает в демо: 100 кадров с неподвижными данными — один пересчёт.
Единственное исключение — пульсация активной цели: она живёт в `update()` (`AnimatedFloat`)
и в параметрах кольца, а не в проекции, поэтому на кэш не влияет.

Копирование данных и проекция кэшируются раздельно: снимок маркеров переносится в `m_snapshot`
только когда сменились источник или `revision`, а камерные поля (позиция, масштаб, область)
входят только в ключ проекции. Иначе перетаскивание карты по каждому пикселу копировало бы
тысячи строк маркеров.

Ссылки на объекты источника между кадрами виджет не держит: маркеры копируются в `m_snapshot`,
а `Projected` и `Cluster` указывают на них индексом. Точность: 1000 маркеров × 100 кадров —
~4–5 мс на кадр при пересчёте (`PerfUI_Test_MapCanvas`, группа 8), в реальной работе пересчёт —
на изменение данных или камеры.

Диагностика: `recomputeCount()`, `projectedCount()`, `clusterCount()`, `gridStepMeters()`,
`recenterButtonRect()`.

## 6. Тесты

`tests/MapCanvasTest.cpp` на `MockRenderBackend` (без ImGui и D3D), регистрация в CTest и xmake:

```
cmake --build build --config Debug && ctest -C Debug -R MapCanvasTest
xmake f -p windows -m debug --builddir="../.builds/PerfUI" -y && xmake run PerfUI_Test_MapCanvas
```

Этап 1 (группы 1–8): проекция мир→экран (курс 90°, «север вверх»), пропорциональность
расстояний, переход дальней цели в стрелку и обратно, вырожденные входы (пустой источник,
`radarRange(0)`, пустой список, диск 2×2, снятие источника до уничтожения), `sameSpace`,
кэш по revision, клик по маркеру и стрелке, бенчмарк.

Этап 2 (группы 9–14): проекция камерой (`+X` вправо, `+Y` вверх, отсечение вне окна, стрелка
активной цели на нужной границе, в том числе когда камера ушла от игрока), линия «игрок → цель»
с расстоянием, зум вокруг курсора и пределы масштаба, панорамирование с упором в границы области
(и центрирование крошечной области), отказ от невалидной области, `centerOn`/`centerOnPlayer`
и следование, кластеризация (число на значке, активная цель вне кластеров, тап приближает),
адаптивный шаг сетки на четырёх масштабах и подписи осей, ввод (колесо, перетаскивание против
тапа, стик, «назад», игнорирование в радаре) и кнопка «центрировать на игроке».

## 7. Ограничения

- Карта схематичная: тайловой текстуры мира нет, только метки, сетка и линии.
- Масштаб плоский: кривизной мира между маркерами пренебрегаем (в пределах десятков километров
  ошибка меньше толщины линии).
- `World` не знает про границы Яса и загрузку регионов — область задаёт хост через `clampToBounds`.
- `MapMarker.id` — то, как мод сопоставляет маркеры между кадрами; сам виджет его не читает.
- Клик по маркеру в `World` не приближает камеру к нему — это решение хоста (`centerOn` + `zoomBy`).
